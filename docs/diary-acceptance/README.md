这是接入 LLM 前的离线基线记录，保留原始失败项供对照。后续真实 DeepSeek 与 Docker 复验见 [LLM 验收记录](../diary-acceptance-llm/README.md)；后续验证时 Docker 已恢复可用。

## 环境与数据

- 使用已审核的 8 篇虚构日记，不使用真实用户数据，不向外部模型发送数据。
- 独立 SQLite 测试数据库位于 `data/runtime/diary-acceptance/`，每次运行新建文件。
- 本地真实 FastAPI + Vite + Edge 无头浏览器；本轮 `LLM_ENABLED=false`，不能据此判断 DeepSeek 的回复质量。
- Python 3.14 + 本地 `.deps` 依赖用于本轮验证，与 Docker 中 Python 3.11 和锁定依赖版本不同。
- 日期按草稿保留，其中部分日期晚于验收当天；跨月回溯可验证，但正式演示前需调整日期。8 篇单篇草稿还不能代表多人物连续情绪轨迹，也不属于正式分类评测集。

## 本轮已修正

记忆检索此前用单字与双字混合 TF-IDF，任何正分都返回，常用问句产生误召回；原文与回应拼接又稀释同原文记录的得分。

现在复用过滤常用问句后的中文双字及英文词项，原文、回应分别计算相似度并取最高分；同分继续优先含回应的记录及较晚日期。两个原有失败回归均已转绿。仍然是词项检索，释义、同义词及长文本检索效果需更多样本验证。

## 后续修正顺序

1. 区分主动查询历史与普通日记叙事，再验证否定语境和多轮对话；“以前”不能单独触发查询意图。
2. 改进否定表达、情绪转折及混合情绪识别，保留人工确认和修改作为最终依据，不针对 8 篇样本硬编码。
3. 统一“开心/积极、平静/平稳”的标签映射，并从同一配置生成日历图例，修正低落、焦虑的颜色索引。
4. 在不输出 API Key 的前提下，单独验证真实 LLM 对快乐分享、低落叙事和自然追问的回应。
5. 修复本机 Docker 启动问题，使用独立 Compose 项目、端口与数据卷重跑，不替换当前用户数据。
