# 聊天回应与记忆保存修正（2026-11-02）

用户指出：聊天应始终回应，输入区应选择保存到 Agent 记忆库或不保存。

## 实现边界

- 默认“不保存”：正常生成回复，本次聊天上下文仍可用于当前会话；不将该段原文写入日记或长期记忆。
- 选择“保存到 Agent 记忆库”：先正常回应，再保存用户原话为 `kind=chat`、`mode=respond`、`response_requested=true`、`allow_retrieval=true` 的来源记录。助手回复不作为用户事实保存。
- 已保存原话可在日记中查看、编辑、补充、确认情绪或删除。聊天中的情绪确认同步到该条已保存记录。
- 全局保存关闭时无法加入记忆库，但聊天始终可用；全局记忆调用关闭时仍可保存，但检索接口返回空结果。
- 临时聊天可通过“加入 Agent 记忆库”明确授权补存；保存失败不影响已生成的回复，可重试，并防止同一轮重复保存。
- 输入区选择对之后发送的消息生效，不会追溯保存先前的临时消息；刷新或离开陪伴页后重新进入默认“不保存”。
- 日记中的“仅保存 / 需要回应”与聊天记忆选择独立。

- `node tests/nature-product.mjs`：10组既有界面与业务场景通过。
- `TEST_URL=http://127.0.0.1:18080 node tests/product-flow.mjs`：首次使用→聊天→建议反馈→日记编辑补充→移动端→隐私与偏好链路通过（LLM关闭的独立Docker实例）。
