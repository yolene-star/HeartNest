# 心栖：自然陪伴风格调整方案

状态：设计提案，待用户验收后迁入正式 React 页面。可点击预览见同目录 `nature-ui-preview.html`。预览仅使用示例内容，不连接模型、日记数据库或真实隐私设置。

## 产品主线

心栖首先是一位有具体形象的情绪陪伴 Agent，其次是用户可以回溯、编辑和补充的心情日记。参考图用于指导视觉和信息层次；健康检测、心率、运动、睡眠、会员、社交广场不纳入本次设计。

## 参考图的细节与迁移

| 参考图细节 | 心栖中的调整 |
|---|---|
| 淡灰绿背景、白色卡片、嫩绿主按钮 | 背景分离内容层次，主按钮使用深色字保证可读性；绿色用于选中与操作，不代表情绪好坏 |
| 健康首页的角色大场景 | 陪伴页顶部使用低对比自然色场景和现有宠物，欢迎语简短，主内容立即进入对话 |
| 圆角卡片、胶囊标签、圆形返回按钮 | 全站统一 20–24px 卡片圆角、胶囊按钮、轻阴影，减少当前细线框和小字号 |
| 心情月历中彩色表情与空白虚线圈 | 心情同时通过表情、文字、颜色区分；未记录与平稳明确区分；同日多种心情展示组合而不取平均 |
| 日历下面按日期排列的记录 | 手机按日期选中后展开当天日记；桌面右栏展示详情，原文、回应、后来补充分段 |
| 记录页“心情 → 影响事件 → 日记 → 保存” | 心情可跳过、事件标签可选、文本为主；“仅保存／需要回应”作为独立选择，不能由心情选项触发自动回应 |
| 自然探索页的分组卡片 | 用于已有建议内容：当前一步、预计耗时、预算、适用范围与来源；用户需要时才展开，不在首页堆砌活动 |
| 底部四项导航 | 手机为陪伴、日记、回顾、我的；日历归入日记，隐私和画像归入我的；桌面同结构侧栏 |

## 用户体验顺序

### 1. 初次使用

保留“宠物自我介绍 → 选择伙伴 → 称呼与沟通偏好”的流程。角色选择可借鉴参考图的层叠卡片，但必须有明确的左右按钮、名称和当前位置；不能自动横向滚动。桌面可并列展示，手机一次突出一个，兼容键盘与减弱动态效果设置。

隐私选择独立说明，默认不调用旧日记；云端模型处理当前输入与历史检索是两件不同的事。角色图像沿用已有独立设计，不用参考图中的绿色角色替换现有宠物。

### 2. 陪伴

顶部绿色场景以“和沐沐在一起”为身份提示，欢迎语示例为“慢一点，也没关系”。宠物与自然色块占首屏约 1/4，避免大场景把输入框挤出首屏。

下方为主对话卡片：清晰区分原话与 Agent 回复，保留情绪确认、保存原话、需要时再给建议等操作。减少卡片边框和非必要说明，但输入区始终提醒“聊天由你决定是否保存”。

桌面右侧放“此刻的心情、写日记、最近一条记录”；手机移到对话后，避免首屏变成状态仪表盘。情绪选择只代表用户自我标记，不建立必须每天打卡的任务。

### 3. 日记

顶部“心情日历／日记列表”切换，避免一级导航同时出现日记、日历和回顾而分散。右上角“写日记”始终可见。

月历采用圆形日期和简洁表情。颜色必须由同一情绪配置生成，统一“平静／平稳”“积极／开心”的兼容映射，解决现有图例错位。空白日期为虚线圈，不能自动显示平静表情；待确认记录不作为已确认状态。

桌面为“月历＋当天详情”双栏；手机纵向排列。点击某天后明确显示日期、记录数与完整日记。打开详情应定位到所选记录，而非跳到所有记录后重新寻找。此深链接行为是后续实现任务，当前预览不代表接口已完成。

详情中的原文、Agent 回应、后来补充分隔展示；修改后仍保留日期和更新时间。写新日记与编辑旧日记使用独立编辑状态，避免当前选中旧日记时原文又填进“新建日记”输入区，造成重复保存。

### 4. 回顾

使用简洁的情绪频次和日期趋势，保留“点开具体经历”的入口。统计只包含用户确认过的记录；空白不算平稳，不使用“健康正常”“心理评分”“状态达标”等结论，也不以红绿暗示情绪优劣。

预览中的柱高仅为说明布局的示例记录条数，不作为真实分析输出。正式版本需接现有统计接口并让柱图和表格表达同一数据。

### 5. 我的

宠物与称呼作为页头，下面分组为陪伴方式、记忆与保存、已确认兴趣。记忆开关与保存开关保留独立说明；兴趣支持来源查看、修改和删除。避免参考图中的连续天数、会员卡或经验值给情绪记录增加负担。

## 视觉规范

| 项目 | 建议 |
|---|---|
| 页面底色 | `#EEF0EA` 灰绿白 |
| 卡片底色 | `#FFFFFF` |
| 主操作色 | `#B6D775` 嫩绿，配 `#293526` 深色字 |
| 主文字 / 次文字 | `#293526` / `#626E5D` |
| 场景色 | 浅鼠尾草绿、奶油白，局部低对比背景，不覆盖长篇文字 |
| 开心 / 平稳 / 低落 / 疲惫 / 混合 | 奶油黄 / 鼠尾草绿 / 雾蓝 / 沙色 / 灰紫，同时附文字或表情 |
| 正文 | 中文系统无衬线字体，产品正文 14–16px、行高 1.7–1.9；辅助信息不低于 12px 为目标 |
| 卡片 / 按钮 | 20–24px 圆角 / 胶囊形，主要触控目标至少 44px |
| 间距 | 手机边距 16–20px；区块间距 16–24px；桌面内容区最大约 1200px |
| 动态 | 150–220ms 的切换与状态反馈；不使用强烈弹跳、自动滚动和连续轮播 |

视觉选择以用户参考图为准。UI/UX 检索中适合迁入的是柔和层次、语义标签、可访问表单和明确导航；通用推荐里的粉紫配色及营销首页结构不适用于本轮，不予采用。

## 常驻宠物与响应式

沿用现有宠物形象、动画、切换与拖动能力。预览仅用现有沐沐静态帧示意占位，不改变资产或动画定位。

桌面宠物与卡片保持独立；手机优先将紧凑的宠物入口整合进底部“陪伴”导航，保持常驻可见并避开输入框、保存按钮和日期格，打开编辑弹层时不遮挡内容。正式页面的手机拖动模式还需定义收起与复位，避免把桌面自由拖动直接缩放到手机。拖动后约束在可见区域，旋转屏幕和视口变化时重新校正。聊天页可展开宠物气泡，其余页弱化气泡但保留可发现的入口。

手机使用底部导航并处理安全区；桌面改为左侧导航，而非把手机界面按比例拉宽。测试宽度至少覆盖 390、768、1024、1440px，并检查文本放大后的可用性。

## 后续落地与验收

1. 经用户确认后，先迁入配色、文字、圆角、间距与统一情绪映射。
2. 调整导航与页面结构，保留已有 API、数据、LLM 和隐私行为。
3. 改善日历详情定位、新建与编辑状态分离、手机底栏和宠物避让。
4. 新增可复跑的浏览器回归：导航、月份与日期、原文编辑、补充、聊天、情绪修正、隐私与删除，以及宠物不遮挡。
5. 执行自动化检查、前端构建、Docker 部署、真实页面复测和截图目视检查，再提交产品版本验收。

此轮只提交设计预览与规范。预览测试不等同于正式产品 API 或功能回归；既有生产页面尚未迁入这套布局。

## 设计预览验证

使用 Edge 检查 390、768、1024、1440px 四种宽度，覆盖四页切换、日历日期与空状态、列表返回日期详情、编辑弹层与预览隐私开关。首轮截图发现手机悬浮宠物遮挡发送区域，已在预览改为底部陪伴导航中的紧凑宠物入口，并重新截图。截图与自动化记录位于 `screenshots/`；检查仅针对独立预览，不代表正式页面已更新。


## 2026-11-02 用户验收修正：聊天与记忆

聊天始终回应。聊天输入区选择“保存到 Agent 记忆库 / 不保存”，默认不保存；保存的是用户原话，并可在日记查看和删除。记忆调用总开关仅决定是否检索历史，独立于逐条存入记忆。日记模式保留“仅保存 / 需要回应”。实现与验证记录见 `chat-memory-validation/README.md`。
