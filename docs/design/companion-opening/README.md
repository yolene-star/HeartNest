# 首页个性化主动开场验证

日期：2026-11-03。使用虚拟日记与隔离实例，不发送真实用户日记到外部模型。

## 行为

首页聊天区显示当前宠物的一句开场，不再显示无针对性的空白区自我介绍。开场不产生新日记、画像或用户消息，作为第一轮聊天的上下文，帮助 Agent 理解用户接话。原有聊天留底与保存选择保持有效。

开启记忆时，`GET /api/companion/opening` 选取最近 7 个北京时间自然日内、允许检索且情绪已确认的记录；优先最新记录日的最多 3 条。同日不同情绪用开放的混合问候；不同日期以较新日期为准。积极/平稳兼容为开心/平静。开场只使用已确认标签，不主动展示正文或个人经历细节。

文案例：

- 疲惫：“你最近记下过有些累的时刻，今天想聊聊近况，还是让我安静陪你一会儿？”
- 开心：“你最近记下了一些开心的时刻，今天有没有什么小事想和我分享？”
- 多种感受：“你最近的心情记录里有不止一种感受，今天想从哪一部分聊起？”
- 无授权/无合适记录/请求失败：“今天想从哪件小事聊起，或者让我安静陪你一会儿？”

有称呼时加称呼。一旦用户开始发送，当前开场固定保留；切页不重复插入，迟到请求不覆盖。刷新网页开启新会话，重新依据最新数据和授权。当前聊天中已显示的开场与原有聊天内容同样留底，不因后台资料修改而改写过去。

## 验证结果

- 新增后端测试先复现 14 项 404 失败，再实现并通过；全量后端 **173 passed**，1 条第三方 Starlette/AnyIO 弃用警告。
- 覆盖通用问候、称呼、开心/平静/疲惫/低落/焦虑/生气/混合、历史别名、未确认/跳过/禁检索/过期/删除排除、补记顺序、用户纠正及关闭记忆。开场无模型调用、无日记或画像写入。
- 前端 Vite 与 Docker 构建通过，隔离环境 18081/18080 完成部署。
- `frontend/tests/companion-opening.mjs` 通过 **5 组真实 Edge 场景**：首句自动显示及记忆关闭、开启记忆后的疲惫问候与首轮上下文、切页保留及新会话混合/开心、服务失败回退、延迟返回不覆盖已开始聊天。
- 桌面 1363×871、手机 390×844 无横向溢出、无页面脚本错误。已打开检查 `desktop-tired.png`、`mobile-positive.png`，聊天输入区和固定页眉/页脚保持可见。
- 原有五套顺序浏览器回归、会话连续性和建议依据回归通过。
- 浏览器测试发现切页返回时开场短暂回退为通用问候；修复了切页触发重新初始化的问题，并复测通过。
- 进行了独立只读代码审查，无待处理发现。

复跑：在 frontend 目录执行 `node tests/companion-opening.mjs`，仅对 18081 公网演示的独立访客数据操作；不可改为个人数据端口 8080。后端测试文件为 `backend/tests/test_companion_opening.py`，使用临时 SQLite 与关闭模型的环境。

## 边界

首版是根据近期已确认标签的定制，不是 LLM 对历史全文的概括或诊断，也不推断用户此刻必然保持同样心情。只有未确认记录时使用通用开场。没有新增跨刷新永久聊天存储、定时推送、弹窗催聊或自动情绪确认。
