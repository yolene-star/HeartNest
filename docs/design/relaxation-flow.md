# 陪伴到放松的衔接

2026-11-02

## 用户路径

- 首页“想放松一下”打开可选方式：去湖边坐坐、试个小办法、继续聊聊。原“陪我待会儿”保留为直接进入湖边的入口。
- 用户明确表示想休息或放松时，正常回应之后可出现一次轻邀请。疲惫标签本身不会触发邀请。
- “先不用”只关闭本次邀请，同一段当前对话不再主动邀请。手动入口仍可使用；不保存拒绝为兴趣画像。
- 湖边沿用现有场景、宠物和聊天区域；返回后历史与草稿保留。
- 小办法调用现有建议接口，沿用建议卡、反馈、替换和可展开的来源与适用范围。场景不宣称研究证明的疗效。

## 边界

主动邀请采用保守的明确请求匹配，排除否定、倾诉限定、历史提问、安全回应、已有建议和已在湖边的情况。尚未引入独立的 LLM 邀请意图分类；表达未命中时可使用手动入口。当前对话不持久化，刷新或离开陪伴页后邀请状态随之重置。

选择框使用原生模态对话框，支持 Escape、键盘焦点约束、退出恢复焦点。继续聊天会聚焦原输入框。小办法请求失败后保留页面错误提示，可重新选择重试。

## 验证

- `frontend/tests/relaxation-flow.mjs`：隔离 Docker 18080，6 组场景，包括主动/手动入口、拒绝、历史与倾诉排除、安全响应、实践来源、换一个、故障重试、不自动写入日记与画像。
- 390、785、1440 宽度的首页与选择框截图；已逐张检查主要手机及桌面画面，按钮可达、无覆盖。
- 既有回归：湖边场景 5 组、主页面 10 组、聊天记忆 5 组通过。
- `frontend/tests/relaxation-default.mjs`：8080 实际 Docker 入口、湖边往返、草稿和存量记录保持。
- 截图与结果：`docs/design/relaxation-validation/`。

隔离验收使用离线回应；安全与故障分支使用明确的模拟响应。未将这些验证等同于在线大模型生成质量评估。
