# 宽屏布局与折叠内容回环

日期：2026-11-03。

## 问题与修正

- 首页继承旧版 `max-width:1110px`，1640px 窗口出现约 151px 纸页右侧闲置区域。取消首页内容最大宽度，聊天区随纸页伸展，桌面侧栏控制在 260–320px。
- 公网说明展开正文继承 `70ch` 限制。改为跟随纸页宽度，短窗口内允许说明单独滚动，避免挤出聊天输入框。
- 320px 下聊天设置折叠摘要曾被省略。改为两行显示，保留 44px 操作目标与紧凑输入区。
- 短窗口的通用规则覆盖窄屏欢迎按钮定位。分别处理平板与手机的短窗口布局，避免按钮裁切或与标题重叠。

## 验证

运行 `cd frontend; node tests/responsive-layout-review.mjs`，使用 Edge 和隔离演示实例 18081，测试数据均为虚构内容。

通过 568×871、1640×900、1920×1080、2560×1440、1363×871、793×871、1363×650、793×650、390×844、320×640 十种窗口。首页内容与纸页右边界间隙均为 0px。检查欢迎按钮边界、页面横向溢出、所有主页面页脚、设置展开/收起、真实聊天回复依据与情绪确认、个人资料提议来源展开；未出现页面 JavaScript 错误。

仓库保留宽屏、短窗口和手机的代表性截图；运行测试可重新生成完整截图。截图按“宽-高-状态”命名，结果见 `results.json`。已实际打开检查宽屏说明、320px 设置展开/折叠与 793×650 欢迎区截图。验证范围为上述流程与尺寸，不代表所有设备与数据组合均不存在问题。

补充：568px 窗口复现了欢迎入口被旧版 `space-between` 规则拉散的问题；650px 及以下改为靠左排列、固定 8px 间距。新增相邻按钮间距断言，修复前失败，修复后重新执行全套回环。
